# AGENTS.md — HR-Automation: связь с карьерным контекстом

Это программная утилита поиска вакансий и CRM откликов. Обзор — [README](README.md),
реализованный контракт — [архитектура](docs/architecture.md).
Этот файл задаёт маршрут к личной карьерной базе; полный LLM-KB-каркас здесь не требуется.
[CLAUDE](CLAUDE.md) — shim `@AGENTS.md`.

## Основная цель проекта

Зафиксировано со слов пользователя 2026-10-17: обеспечивать два стабильных потока вакансий.

1. **Приоритет 1 — следующая работа.** Релевантные и подходящие вакансии, оптимальные
   для следующей работы пользователя с учётом его актуального карьерного вектора
   и подтверждённых критериев.
2. **Приоритет 2 — практика собеседований.** Менее релевантные вакансии, на которых
   пользователь может практиковать прохождение собеседований, чтобы оттачивать
   навык для вакансий первого приоритета.

При развитии поиска, отбора и CRM учитывать оба назначения. Поток практики служит
подготовке к собеседованиям на приоритетные вакансии. Эти приоритеты не приравниваются
автоматически к категориям A/B/C или баллам; изменения исполняемых критериев проходят
по правилам ниже.

## Карьерный контекст

Перед изменением профилей/правил или оценкой соответствия пользователя роли прочитать
[мост с career-orientation](../aramais-vault/codex/projects/career-orientation/codex/hr-automation.md), затем только релевантные
канонические страницы по [INDEX](../aramais-vault/codex/projects/career-orientation/codex/00_INDEX.md).
При работе только над кодом достаточно знать маршрут; всю личную базу заранее не загружать.

Профессиональный профиль, навыки, кейсы и принятые карьерные решения живут в career-orientation.
Исполняемые критерии/веса — в локальном config; вакансии, оценки и CRM — в SQLite HR.
Широкие enabled streams, score и runtime goal/budget не устанавливают намерения пользователя.
Если источники расходятся, назвать расхождение и даты; исторический самоотчёт не считать текущим.

При изменении критериев показать файл/поле, текущее/новое значение и основание;
сохранять стабильные profile ID и учитывать устаревание прежних оценок.
Для запросов чтения использовать маршрут моста: готовые отчёты либо подтверждённый SQLite
в режиме read-only. Экспорт/старт CRM может мигрировать базу; не выдавать его за чистое чтение.
Статусы и следующие действия откликов сохраняют единственный канон в HR; не зеркалить их в CAR-backlog.
Материалы резюме опираются на доказательства кейсов; ИИ-переформулировки не подтверждают достижение.

## Perplexity Search API

Перед изменением интеграции Perplexity прочитать
[сохранённую инструкцию пользователя](docs/perplexity-search-integration.md), затем
проверить актуальную официальную документацию по указанным там ссылкам.
Для discovery выбран Search API: структурированные результаты для обработки в проекте.
Ключ — только `PERPLEXITY_API_KEY`; не выводить, не логировать и не сохранять в Git.
