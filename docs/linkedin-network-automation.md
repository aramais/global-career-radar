# Расширение сети LinkedIn

Это отдельный процесс в локальном Codex: ежедневные приглашения для поиска работы
на рынке Бразилии и самостоятельный отзыв старых непринятых приглашений. Его
расписание задаётся штатными автоматизациями приложения; сбор вакансий и CRM
не запускают эти действия.

## Исполнение и состояние

- `scripts/linkedin_network_journal.py` — версия проверок и операций журнала в Git.
  Скрипт работает только с локальными файлами, не обращается к LinkedIn и не
  управляет браузером.
- `data/local/linkedin-network/state.json` — единственный изменяемый журнал:
  контакты, подтверждения, дневные счётчики, ступень, очередь, даты, блокеры и ID задач.
- `data/local/linkedin-network/user-request.txt` и `query-bank.json` — действующий
  полный запрос пользователя и 210 запросов Google.
- `data/local/linkedin-network/daily-prompt.txt` и `cleanup-prompt.txt` — сохранённые
  инструкции задач. Их активные копии хранятся в автоматизациях приложения.
- `data/local/linkedin-network/cycle.lock` — общая атомарная блокировка для обоих
  процессов владельца `linkedin:malkhasyan`.

Каталог `data/local/` исключён из Git. Журнал контактов, история действий, скриншоты
и настройки автоматизаций приложения не восстанавливаются одним `git clone`.
При потере состояния нужно восстановить его из подтверждений или резервной копии;
начинать заново с нулевым счётчиком запрещено. Скрипт сам журнал не создаёт.

Сохранённые задачи вызывают `data/local/linkedin-network/journal.py`. Этот локальный
совместимый вход делегирует исполнение версионируемому скрипту, поэтому обновление
Git меняет исполняемые проверки без переноса журнала и смены пути в заданиях.

Чтение без изменения состояния:

```bash
python3 scripts/linkedin_network_journal.py status
```

## Контракт процесса

До активной настройки нужен явный ответ пользователя Premium/обычный, сохранённый
с источником и привязкой к профилю `malkhasyan`. Наблюдение Premium в интерфейсе
не заменяет этот ответ. Перед каждым действием проверяются сохранённое подтверждение
и текущий аккаунт в штатном браузере.

Ежедневная задача работает в 09:00 `America/Sao_Paulo`. Ступени — 5, 10 и 13
подтверждённых приглашений за календарный день. Повышение разрешено после семи
последовательных успешных дней на ступени, действует со следующего дня и не
использует старую успешную неделю после простоя. Минимальный интервал между
исходящими приглашениями и сообщениями — 240 секунд от подтверждения предыдущей
отправки. Ручные отправки также учитываются; недобор прошлых дней не компенсируется.

Обнаружение людей идёт через Google с `site:linkedin.com/in/`. Сначала проверяются
IT/Data-рекрутеры и потенциальные нанимающие руководители, затем коллеги-лиды и
аналитики. География — рынок Бразилии; расширение требует решения пользователя.
Обычные приглашения отправляются без записки. Сообщения и InMail требуют отдельного
поручения. Полные критерии, бюджеты и курсоры находятся в действующем локальном
запросе и журнале, а не выводятся из enabled streams поиска вакансий.

При лимите инвайтов ежедневная задача остаётся активной. Будущий явный срок LinkedIn
приоритетнее; без срока следующая попытка назначается на следующий календарный день
в 09:00. В назначенный день разрешена одна реальная попытка подходящему контакту.
День попытки и следующая дата сохраняются до действия. Подтверждённый успех входит
в дневной счётчик и возобновляет процесс на ступени 5. Неизвестный результат сначала
восстанавливается; исчезновение предупреждения не доказывает снятие лимита.

Отдельная задача очистки работает раз в 21 день в 09:00. Отзываются только pending
строго старше одного календарного месяца. Порог учитывает длину прошлого месяца;
равенство порогу не подходит. Дата без времени должна быть раньше календарной даты
порога. Округлённый возраст, например «1 месяц назад», не заменяет надёжную дату.
После полного успешного охвата следующая очистка — через 21 календарный день в 09:00.
Обновление инструкций не сдвигает уже сохранённую дату.

Отозванные контакты удаляются из очереди и не приглашаются повторно автоматически,
включая варианты URL с языковым суффиксом. Отзыв не обнуляет счётчик и не снимает
лимит инвайтов. При ограничении только отправок доступная штатная очистка допустима;
CAPTCHA, проверка личности и предупреждения безопасности останавливают действия.

## Операции журнала

Каждый изменяющий вызов требует ID текущего владельца блокировки. `begin` создаёт
её атомарно; чужую или оставшуюся после сбоя блокировку нельзя удалять без проверки
владельца и сверки неизвестных результатов.

| Команда | Назначение |
|---|---|
| `begin` / `end` | Начало и завершение цикла с общей блокировкой |
| `contact` / `query` | Проверки контактов, бюджеты и история запросов |
| `evidence` | Уточнение доказательств без изменения отправки и счётчика |
| `reserve` / `confirm` | Сохранение намерения до отправки и результата после UI-подтверждения |
| `limit-hit` | Явный отказ из-за лимита и следующая разрешённая попытка |
| `withdraw-reserve` / `withdraw-confirm` | Проверка срока, pending и даты; затем подтверждённый отзыв |
| `finalize` | Итог дня и план повышения на следующий день |
| `cleanup-finalize` | Полный охват очистки, результат и следующая дата |
| `patch` | Прочие поля состояния; защищённые поля действий изменяются отдельными командами |

JSON-аргументы и обязательные проверки определены в скрипте. `reserve` и
`withdraw-reserve` не нажимают кнопок: действие делает агент через обычный интерфейс,
затем отдельно подтверждает результат. Пока исход действия неизвестен, новый
исходящий вызов блокируется.

При обновлении процесса сохраняются контакты, дневной факт, ступень, успешные дни,
очередь, подтверждение аккаунта и даты. Дополнительная отправка или очистка для
проверки обновления не запускается.

## Проверка расписаний

После создания или изменения задачи нужно прочитать сохранённые инструкции и
проверить фактические `next_run_nominal_at` и `next_run_at` в часовом поясе São Paulo.
Одного текста RRULE недостаточно: приложение может интерпретировать время в UTC
и запускать подготовку на несколько минут раньше или позже номинала. Ранний запуск
должен дождаться локальных 09:00; дату `next_cleanup_at` при этом не меняют.

Если отдельный график не может точно следовать сохранённой дате очистки, ежедневная
задача проверяет эту дату и выполняет очистку под той же блокировкой, без дубля.
Включённый Mac, работающее приложение, Chrome с подключённым расширением и входом
в нужный аккаунт — условия локального исполнения. Созданное расписание и ручной
цикл не являются доказательством состоявшегося фонового запуска.
