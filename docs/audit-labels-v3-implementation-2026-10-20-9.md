## 4. Находки

### A9-M1 — средняя: эксклюзивные отчёты ломают команды с путём по умолчанию

**Суть.** Общий писатель `write_text_report` теперь отказывается писать в занятый путь
(`eval_runner.py:440–466`, ошибка на `:454`). Так же устроены accuracy, rules-diff и
сравнение классификаторов. Но пути по умолчанию остались фиксированными:
`latest.json` (`cli.py:399`), `gold-validation.json` (`:551`),
`accuracy-{variant}.json` (`:765`), `rules-diff.json` (`:811`).

**Доказательство (проверено).** На рабочей копии `data/local/eval/latest.json` лежит с
10.10. Команда `.venv/bin/job-intake eval --limit 1` завершается ошибкой «Report output
already exists; choose new paths». Аудитор её воспроизвёл. `gold validate` без
`--output` сработал один раз, после чего упал бы так же. README в разделе «Проверка
сохранённой разметки (`eval`)» по-прежнему пишет «По умолчанию JSON-отчёт сохраняется в
`data/local/eval/latest.json`» (README:568–569). Первый пример этого раздела на рабочей
копии не работает. Новое правило описано только ниже, в разделе labels-v3 (README:666).

**Последствие.** Это изменение повседневной команды `eval`, не относящейся к labels-v3, —
вопреки §0.9. Данные не теряются, но каждый запуск без `--output` требует ручного
выбора имени. Прежние аудиты (A6-C1, сравнения в -7/-8) приняли контракт как
описанный, но путь по умолчанию с существующим файлом не проверяли.

**Рекомендация (решение пользователя).** Варианты:
- имена по умолчанию с меткой времени запуска (`latest-<UTC>.json`), сохраняя
  эксклюзивность;
- либо прежняя атомарная замена только для неэталонных отчётов `eval`/`rules-diff`;
- в любом случае исправить README:568–569 и help команд.

### A8-M1 — средняя (повторно подтверждена): смещение страницы до принятия ответа

**Суть.** Обработчики «Вперёд»/«Назад» меняют `goldOffset` до запроса
(`index.html:2062–2063`), а `refreshGold` подтверждает смещение только при принятом
ответе (`:1711–1717`). Отменённый запрос оставляет смещение будущей страницы.

**Доказательство.** Выведено по коду; браузером не воспроизводилось. Сценарий описан
в восьмом аудите.

**Последствие сейчас.** При 171 строке и странице 100 запрос пустой страницы
откатывается к последней непустой (`:1713–1715`), поэтому пропуск маскируется. При
разметке до 300+ строк навигация начнёт пропускать по 100 карточек.

**Рекомендация.** Хранить запрошенное смещение отдельно и коммитить `goldOffset` только
вместе с принятым ответом. Регрессионный тест — через обработчик кнопки.

### A9-L1 — низкая: слияние тегов найма теряет нераспознанное ограничение

**Суть.** Если `hiring_geography` открыт для Бразилии, а `work_authorization` требует
страну вне таблицы алиасов, второй тег отбрасывается. Результатом становится
`open_to_brazil` (`gold_v3.py:104–134`, отброс на `:120–122`).

**Доказательство (проверено).** Вход: `brazil_explicit` + `country_required`, страна
«Kenya». Выход: `hiring_eligibility = open_to_brazil, basis explicit`. Ограничение
упомянуто только в списке `dropped_tags` manifest.

**Последствие.** Сейчас никакого: в v2 нет человеческих тегов, новые метки ставятся
в UI v3. Но направление ошибки разрешающее, то есть противоположно консервативному
принципу миграции.

**Рекомендация.** Если компонент `country_required` отброшен, не переносить
`hiring_eligibility` целиком и записать причину в manifest. Добавить тест.

### A9-L2 — низкая: две `write_new_text` с противоположным порядком аргументов

**Суть.**
- `cohorts.write_new_text(path, content)` (`cohorts.py:61`) используют accuracy,
  eval_runner, frozen и evaluation_cli.
- `gold_workbook.write_new_text(content, output)` (`gold_workbook.py:53`) использует
  gold UI (`gold_ui.py:35`, вызов `:470`).

**Последствие.** Сейчас вызовы корректны, но перепутать функции при правке легко.
Ошибка проявится только во время выполнения.

**Рекомендация.** Оставить одну реализацию, а вторую заменить тонкой обёрткой с
именованными аргументами.

## 5. Признанные отклонения

Отклонения из прежних отчётов (аргумент `company=`, `required_domain`/`basis` в схеме
ответа, `label_scope`, раздельные метрики `domain_fit`, MAE/QWK по покрытым парам,
v2-only `build_bundle`, отложенные `LabelResult`) аудитор считает обоснованными. Они
отражены в design doc. Пример Tiger Analytics design doc теперь честно не обещает
воспроизвести (§11), и это корректно. Переход метрик на `relevance-scale-v2` и
`frozen-task-metrics-v2` с воспроизведением v1 тоже корректен: реальные прогоны
проходят, статусы реального сравнения не изменились.

## 7. Готовность к следующим фазам

- **P0:** принят.
- **P1:** хранилище принято. Навигация — после A8-M1. Визуальная проверка в браузере
  остаётся за пользователем.
- **Операционно.** CRM уже открывает `vacancy-labels-v3.jsonl` по умолчанию (README:122,
  `gold_ui.py:206`). Новые метки пишутся в v3, `vacancy-tags-v2-labeled.jsonl`
  перестаёт пополняться. `eval accuracy --variant saved` и `eval frozen freeze`
  принимают только v2 и новых меток не увидят.
- **Предпосылки P2.**
  - v3-freeze: `build_bundle` использует только `validate_gold`, `frozen_eval.py:148`;
  - реестр когорт для прецедентов;
  - перенос `annotation/scope.py`;
  - `LabelingConfig`;
  - решение по A9-M1, иначе экспорт и отчёты пилота будут упираться в занятые пути.
