исключения в журнале оценки. Batch-state и lock-файлы доступны только владельцу
на POSIX. Неопределённый результат отправки проверяется через удалённый API;
невосстановимый результат останавливает обработку вместо повторной платной отправки.

## Измерения после исправлений

Нагрузки синтетические: SQLite в памяти, fake AI, без реальных ключей, cookies,
писем, рабочей базы и платных запросов. Время зависит от машины и режима замера.

| Сценарий | До | После |
| --- | ---: | ---: |
| CRM: 1000 вакансий и 1000 откликов, SELECT | 3006 | 16 |
| CRM: размер JSON | 13 310 088 байт | 500 569 байт |
| CRM: пиковая память под tracemalloc | 86,95 МБ | 8,07 МБ |
| CSV: 1000 вакансий, limit=1, SELECT | 1001 | 2 |
| CSV: время limit=1 | около 0,226 с | около 0,034 с |
| Проверка кеша: одна вакансия, 6 профилей, SELECT | 13 | 2 |
| Checkpoints: 600 000 символов, сериализовано | 132 153 499 байт | 898 967 байт |
| Prune: 1000 старых вакансий, SELECT | 4002 | 0; пять DELETE |
| Prune: время | около 0,35 с | около 0,010 с |

CRM теперь отдаёт страницу из 100 вакансий и компактные сведения о 1000 откликах;
описания и история доступны по запросу. Поэтому уменьшение JSON и памяти включает
изменение объёма первоначальной загрузки. Контракты полных деталей и CSV сохраняются.

В браузере на отдельной временной базе проверены поиск вакансии за пределами первых
1000, загрузка описания, массовая архивация двух вакансий и исправление даты/заметки
текущего этапа с сохранением одного события и корректных метрик.

Финальный общий прогон: **1176 тестов прошли за 8,70 с**, `ruff check src tests`
и `git diff --check` без замечаний. Проверки нового контракта компактных списков
сохраняют прежние требования к цитатам, приватным полям, полной истории и заметкам:
они проверяются через endpoints деталей. Тест async UI подтверждает один запрос
деталей при повторном раскрытии и отсутствие дублирующихся доказательств.

## Применение

Перезапустите ранее запущенный сервер CRM. При открытии базы миграция добавит версию
компаний, сохранив существующие записи. Для локального пересчёта неархивных вакансий:

```bash
.venv/bin/job-intake reevaluate --config config/settings.yaml
```

Эта команда использует сохранённые источники и локальные правила. Новая независимая
проверка моделями запускается явно через `annotate --ai` с выбранной конфигурацией.
Состояние классического LLM batch хранится в `data/local/llm-batches`; его удаление
приведёт к потере связи с уже отправленными задачами. Подробности — в README.
Сохранение состояния относится к задачам, отправленным новой версией. Идентификаторы
задач, потерянные старой версией до исправления, автоматически восстановить нельзя.

Защита CSV проверена на сериализованных значениях; повторное сохранение в табличном
редакторе может менять интерпретацию ячеек. Реальные API провайдеров и повторный аудит
зависимостей на CVE в этой задаче не проверялись.
