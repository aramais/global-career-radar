# Поиск вакансий по положительным примерам

Discovery пополняет обучающую выборку новыми вакансиями, которые человек может
подтвердить как релевантные. Машинное сходство определяет очередь просмотра;
положительным результатом считается человеческая `relevance >= 2`, сильным — `3`.
Условия найма и пригодность для практики интервью не выводятся из этой оценки.

## Первый запуск

Все команды выполняются из корня HR-Automation. `PYTHONPATH=src` позволяет работать
непосредственно с исходниками текущего окружения.
Если план `2026-10-18.json` уже подготовлен, начните с `discovery run`; для повторного
планирования выберите новое имя файла.

```bash
cd /Users/admin/Documents/HR-Automation

# Без API. Проверяет человеческие метки и исходники; SQLite открывает только read-only.
PYTHONPATH=src .venv/bin/job-intake discovery plan \
  --gold data/local/gold/vacancy-tags-v2-labeled.jsonl \
  --output data/local/discovery/plans/2026-10-18.json

# Платный этап: ключ PERPLEXITY_API_KEY в окружении или локальном .env.
# Папка запуска должна быть новой. Бюджет обязателен.
PYTHONPATH=src .venv/bin/job-intake discovery run \
  --plan data/local/discovery/plans/2026-10-18.json \
  --output data/local/discovery/runs/2026-10-18-01 \
  --budget-usd 10 --max-concurrency 4 --max-details 200

# Формирует новую слепую партию: до 40 приоритетных + 10 случайных из остальных.
PYTHONPATH=src .venv/bin/job-intake discovery prepare-labeling \
  --run data/local/discovery/runs/2026-10-18-01 --size 50 --random-size 10

# Кандидаты открываются в CRM; их исходники не импортируются в рабочую jobs/CRM базу.
PYTHONPATH=src .venv/bin/job-intake crm serve \
  --discovery data/local/discovery/runs/2026-10-18-01
```

Откройте http://127.0.0.1:8765. В discovery-режиме стартовый экран — разметка
кандидатов. Выберите профессию, релевантность 0–3 и условия найма, сохраните ответ.
Кнопка «Стоимость и время поиска» показывает агрегированный отчёт. Исходный текст,
seed, машинный приоритет и провайдер в human-ответы не копируются; приоритет и
происхождение поиска в редакторе скрыты. Обычная gold-разметка остаётся доступной
при запуске без `--discovery`; `--gold` и `--discovery` взаимоисключающие.

Сам `crm serve` сохраняет обычную инициализацию/миграции рабочей SQLite. Проверка
исходников discovery и сохранение его меток работают с файлами запуска, без записи
кандидатов или откликов в рабочую базу.

```bash
# Только чтение результатов. Файл отчёта должен быть новым.
PYTHONPATH=src .venv/bin/job-intake discovery report \
  --run data/local/discovery/runs/2026-10-18-01 \
  --output data/local/discovery/reports/2026-10-18-01.md
```

Без `--output` команда печатает JSON. Суффикс `.md` создаёт текстовый отчёт,
остальные суффиксы — JSON. Разметку, план и завершённые запуски команды не заменяют.

## Образцы и план поиска

Источники — только датированные человеческие метки `blind` / `assisted` с
релевантностью 2 или 3. Незаполненные ответы и 1 не становятся отрицательными.
Шесть исходных положительных примеров с профессией Analytics Leadership не
ограничивают поиск этой профессией. Положительный пример без профессии/условий
найма можно использовать для поиска по содержанию, сохраняя пропуски человеческих
ответов.

Планировщик извлекает реальные обязанности, строит варианты названий и запросов
по содержанию, распределяет задания между образцами. По умолчанию 80% запросов
развивают образцы, 20% расширяют поиск по датированному карьерному вектору.
Поисковые фразы ограничены 128 символами, версии алгоритма/критериев сохраняются.
Слова о компании и требования к прошлому опыту не служат доказательством обязанностей.
Цитаты о pricing, monetization или causal inference не превращаются в обязательные
критерии; действующие профили, веса и стабильные profile ID не меняются.

`--holdout FILE` исключает контрольные вакансии из образцов и новых результатов.
Не используйте независимые тестовые примеры для построения запросов или настройки
поиска. Примеры, использованные как seeds, становятся данными разработки.

Для следующего раунда можно добавить новые человеческие ответы:

```bash
PYTHONPATH=src .venv/bin/job-intake discovery plan \
  --gold data/local/gold/vacancy-tags-v2-labeled.jsonl \
  --feedback data/local/discovery/runs/2026-10-18-01/labels.jsonl \
  --output data/local/discovery/plans/round-02.json
```

Исторический gold хранит source hash с полной исходной metadata, а snapshot —
только разрешённые исходные поля. Поэтому план сверяет такие записи с подтверждённой
SQLite через `read_saved_records(..., include_archived=True)` в режиме read-only.
Для другой базы можно указать `--config` или `--database`. Новые discovery-snapshot
самодостаточны; их hash вычислен по точно сохранённым исходным полям.

## Поиск и ранжирование

Perplexity Search возвращает ссылки, затем загрузчик получает полный текст с
публичного первоисточника: ATS API, JobPosting JSON-LD или проверяемой HTML-страницы
с обязанностями и признаками вакансии. Search snippet не считается полным текстом.
Закрытые и неполные объявления не попадают в партию, но их получение входит в расходы.
Браузерный рендеринг и обход страниц, требующих авторизации, в этот MVP не входят;
такие страницы отражаются как неудачные загрузки.

Локальное ранжирование по обязанностям и примерам работает без дополнительной API.
Для смыслового сравнения через Gemini укажите модель и явные тарифы своего проекта:

```text
discovery run ... --semantic-model MODEL \
  --input-per-million INPUT_USD --output-per-million OUTPUT_USD
```

Нужен `GEMINI_API_KEY`. Модель получает обязанности положительных примеров и кандидата,
возвращает приоритет и ID подтверждающих исходных фрагментов. Несуществующие evidence,
незавершённый JSON и ошибки оставляют локальный приоритет; зарезервированные расходы
сохраняются как неопределённые. Модель не выставляет человеческую релевантность.
Профиль пользователя, резюме и контакты поисковому провайдеру не передаются.

Известные вакансии исключаются по исходникам gold/holdout, по всей подтверждённой
SQLite, включая архив, и по кандидатам прежних запусков в той же родительской папке.
Для другой папки запуска используйте повторяемый `--known-run PATH`. Внутри запуска
объединяются canonical ATS URL/алиасы и точные текстовые копии; разные известные
requisition ID не объединяются только из-за одинакового текста. Существующие HR UID
не переписываются. При объединении сохраняются все поисковые происхождения.

## Расходы, время и ограничения измерения

`--budget-usd` ограничивает резервирование оплачиваемых запросов с учётом параллельности.
По умолчанию используется измерительный тариф web Search POST 0.005 USD, сохранённый
со ссылкой на [Perplexity pricing](https://docs.perplexity.ai/docs/getting-started/pricing).
При изменении тарифа задайте `--search-price-usd`. Это расчётная оценка, не счёт провайдера.
Для Gemini оплачиваемый output включает thinking tokens. Перед запросом резервируется
консервативная оценка максимального объёма; известный usage уточняет расчёт.
При таймауте или неизвестном списании резерв остаётся в расходах и помечается отдельно.
Автоматических повторов оплачиваемого POST нет. Локальные вычисления, подписки,
разработка и стоимость часа пользователя в USD не оцениваются.

В отчёт входят все расходы запуска, включая нерелевантные, повторные, закрытые
результаты и неудачные попытки. Знаменатель — уникальные новые кандидаты этого запуска
с датированной человеческой `relevance >= 2`. Машинный приоритет и незаполненная метка
не увеличивают знаменатель. При нуле положительных стоимость/время на положительный
равны `null` («не определено»).

Отдельно считаются:

- прошедшее время выполнения поиска и секунды поиска на положительный пример;
- активное время всей сохранённой разметки и секунды на положительный пример;
- человеческая релевантность 2/3, сильные совпадения 3 и завершённость всех трёх ответов;
- точность приоритетной и случайной частей по отдельности;
- условия найма среди релевантных и покрытие учётом времени.

Таймер исключает скрытую/неактивную вкладку и длительный простой. Учитываются интервалы
до сохранения изменившегося ответа; несохранённое чтение, повторное чтение без изменения
ответа и работа вне CRM не измеряются. Повторный запрос сохранения не удваивает время.
При частичном отсутствии временных событий итоговое время на релевантный пример — `null`.
Сбой между сохранением метки и временного события восстанавливается журналом;
read-only отчёт учитывает уже подтверждённую запись журнала без повторного сохранения.

Набор, обогащённый положительными примерами, храните отдельно от случайной контрольной
выборки обычного потока. Precision такой партии не измеряет долю релевантных на рынке
или recall поиска. Повторите сопоставимый запуск для оценки стабильного нового потока.

## Файлы запуска

| Файл | Содержание |
|---|---|
| `plan.json` | Образцы, источники, версии и задания |
| `manifest.json` | Лимиты, все API-расходы, время, ошибки и остановка |
| `discoveries.jsonl` | Все найденные ссылки и поисковые происхождения |
| `candidates.jsonl` | Зафиксированные полные исходники и отдельные машинные приоритеты |
| `batch.json` | Top/random принадлежность, случайное перемешивание и digest исходников |
| `labels.jsonl` | Только исходники и человеческие ответы в текущей gold-схеме |
| `review-events.jsonl` | Уникальные события сохранённого человеческого времени |

Папки содержат приватные материалы и располагаются внутри исключённого из Git `data/local/`.
